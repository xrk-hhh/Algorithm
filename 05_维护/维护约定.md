# 维护约定

## 目录与版本

1. 原始源码归档按平台、比赛和模板类型保存在 `02_模板`、`03_题目`、`04_训练与工具`；早期 `.c` 不强制改扩展名。
2. 本次恢复方法统一在 `06_解法整理/<原归档路径>/<方法编号>.cpp`，头部注明来源、原文行号和恢复层数。新增题目可直接按平台归档为活跃源码，无需再造一份注释稿。
3. 同题多方法分别命名并写 README：算法思路、适用条件、复杂度与已知问题。历史失败和实验版本保留真实状态，不自动标为正确解法。
4. 修改恢复版时记录理由；原稿用于追溯，不同步覆盖。若更新网站文章，保留标签并同步知识分类和代码总索引。

## 注释处理

整文件注释可能保存多套完整程序、接口类、函数实验和方法内部的替代方案。按实际注释层级、main/类/函数边界识别，不能一次性去掉所有 `//`。恢复方法内部的注释继续作为注释。接口类不强求 main，函数片段标明用途。

## 编译标准

默认 GNU C++14，早期 C 代码按 C11 检查。使用 GCC 的 `bits/stdc++.h`、`__int128` 等扩展需符合评测环境。每个 main 独立编译，不把整个目录链接成一个程序。

```powershell
g++ -std=c++14 -Werror -finput-charset=UTF-8 -fsyntax-only "方法01.cpp"
gcc -std=c11 -finput-charset=UTF-8 -fsyntax-only "方法01.c"
```

原稿可能含结构化绑定等较新语法；本次恢复版已改写为 C++14 成员访问，并保留适配记录。语法通过、样例通过与 AC 分开记录。

## Git 提交

扩展名白名单主要允许 `.cpp`、`.c`、`.md`、必要头文件和 Git 规则；`.maintenance/` 是本次本地处理数据，不提交。编译输出放仓库外或被忽略的构建目录。

```powershell
git status --short
git add --all
git diff --cached --stat
git diff --cached --name-only
git commit -m "docs: 更新算法代码与分类索引"
git push origin main
```

提交前检查文件类型、相对链接、C++14/C11 语法，以及实际修改涉及的样例和边界。题目通过状态只来自实际评测记录；不要沿用旧报告作为新代码的正确性保证。
