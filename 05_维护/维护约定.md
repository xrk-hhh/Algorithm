# 维护约定

## 放置规则

1. 普通题目放 `03_题目/<平台>/<比赛或专题>/题号_题名.cpp`；每个程序独立编译。
2. 可复用模板放 `02_模板/<算法专题>/`，应用题可以只在专题索引中建立链接，避免重复维护。
3. 笔记放 `01_知识笔记/`；文章应说明适用条件、核心不变量、复杂度和边界，题解附题目链接。
4. 训练赛与对拍放 `04_训练与工具/`，历史稿和已验证程序分别注明状态。
5. 早期 C 代码保留 `.c`；不为统一扩展名强制改成 C++。

## 添加或修改内容

- 同步更新对应目录 README、知识专题索引和代码总索引；新题明确标注算法标签的依据。
- 网站文章保留原标签；复制时补齐 `.md` 相对链接，检查插图和公式。
- 历史源码保持语义，格式可规范为 UTF-8/LF；大幅改写或修复前记录旧版与更改理由。
- 全注释稿只是学习记录；若恢复运行，建议另存带说明的版本，并对样例和边界做验证。

## 编译约定

GNU C++17 和 C11 是本次语法检查基准；题目需要其他标准时在文件或题解中说明。`bits/stdc++.h`、`__int128` 等扩展依赖 GCC。每个题目的 main 独立，不能把整个目录当作一个链接目标。

```powershell
g++ -std=c++17 -fsyntax-only "03_题目/平台/题目.cpp"
gcc -std=c11 -fsyntax-only "03_题目/洛谷/入门题.c"
```

## Git 提交

本仓库采用扩展名白名单，主要纳入 `.cpp`、`.c` 和 `.md`，另外允许头文件及两个 Git 规则文件。`.maintenance/` 是本次整理的本地工作数据，不提交。文件白名单能阻挡 `.exe/.o/.cph` 等生成物，但仍需人工确认提交内容。

```powershell
git status --short
git add --all
git diff --cached --stat
git diff --cached --name-only
git commit -m "docs: 更新算法题解与知识索引"
git push origin main
```

题目通过状态应来自实际评测记录；“含main”或“语法通过”不能替代 AC。更新时同时维护 `校验报告.md`，不要把旧的验证结果套用到新代码。
